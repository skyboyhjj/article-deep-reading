# 读解（Deep Read）

[![ci](https://github.com/skyboyhjj/article-deep-reading/actions/workflows/ci.yml/badge.svg)](https://github.com/skyboyhjj/article-deep-reading/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python 3.12+](https://img.shields.io/badge/python-3.12%2B-blue.svg)](https://www.python.org/)

**在线演示**：<https://deepread.hui-skill.cn>（慧惠 · 数据环保卫士）

把一篇文章拆开核验的**方法与服务**。不是摘要器，不是评论器。

给它一样东西 —— **链接、一段正文、或一段音视频** —— 它做四件事：**判体裁、数作者序、逐条对依据、能算的地方真算一遍**，然后出一份标明「确证 / 不实 / 半对 / 未核」的报告。

之所以需要它：大多数「帮你读文章」的工具产出的是**更通顺的复述**。而复述解决不了真问题——这篇讲的对不对、那个数字站不站得住、作者序有没有被换过。

---

## 它凭什么不一样

| 常见做法 | 这个项目 |
|---|---|
| 让模型总结全文 | 让模型**找可核项**，逐条判「确证 / 不实 / 未核」 |
| 涉及数字就复述 | 让模型给出**表达式**，服务端用白名单求值器**真算**，算不出就标「未实算」 |
| 报告由模型一气写出来 | 数字**只从实算记录流入**报告，不经模型之手（防它把算准的数改写） |
| 抓不到就编 | 抓不到就明说，并提供**粘贴正文**与**上传音视频**两条路 |
| 通篇挑错 | 强制写一节**它讲对了什么** |

最后一条不是修辞。只挑错的读解没有公信力，也容易为了凑数把对的说成错的。

## 一个真实例子

公众号长文《群作用与计数：轨道公式、Erlangen 纲领及 Burnside 引理详论》（公众号「数学科学的探索之旅」，2026-04-04，约 2.1 万字、17 个例题、6 道习题）。完整读解与算据都在 [`examples/`](examples/)，脚本只依赖标准库，可以自己跑。

结论先给（读解 §0 原文）：

> 三个主定理——轨道公式、Burnside 引理、Polya 定理——的陈述和证明都是对的……但例12（二面体群下的项链）算错了：6 珠黑白、旋转加反射等价，答案是 13，文中写 11。错因不在代入，在公式本身——偶数 $`n`$ 时把两类反射轴当成了同一类。

**这句话不是模型读出来的，是算出来的。** 脚本对每个可数结论都算两遍：一遍按文中公式，一遍用置换群暴力枚举轨道，再与文中数字三方对账。实跑输出：

```
与文中一致：例11(14) 例13(333) 例14(12) 例15(3) 例16(5) 例17(4)
            习题2(5) 习题4(10) 3.7.1(3)
与文中不一致：例12 → 真值 13，文中 11（错因在反射的循环结构）
术语错误：2.3.4 把 CO(n)（相似群）当作共形群
```

十处数值，九处对上、一处硬错。**报告先说对的部分** —— 只挑错的读解没有公信力；而错的那一处是公式级，不是抄错数字。

错在哪，手算就能看清（6 珠、两色，Burnside）：

| 项 | 贡献 | 小计 |
| :-- | :-- | --: |
| 旋转 6 类 | $`2^6 + 2\cdot 2^1 + 2\cdot 2^2 + 2^3`$ | 84 |
| 反射 3 条过对顶点轴 | $`3 \times 2^4`$ | 48 |
| 反射 3 条过对边中点轴 | $`3 \times 2^3`$ | 24 |
| 合计 | $`(84+48+24)/12`$ | **13** |

关键在第二行：过对顶点轴的 4 个不动点来自「轴上那两个顶点各自固定，其余 4 个成 2 对」，所以不动染色数是 $`2^4=16`$，不是 $`2^3`$。文中把这一轴当成「无不动点」，于是 $`(84+24+24)/12 = 11`$ —— 正好是它写下的那个数。**错误能精确复现，这才是判它错的依据。**

### 报告分两层：简约版看结论，详细版看依据

一次把结论、统计、逐条核验表、算据全给出来，读者多半只看头几行就下判断 —— 而判断恰恰最需要依据来核。所以读完立刻看到的是**简约版**：一句话结论、站得住的部分、需要改的和算不上的。

想知道某一条凭什么这么判，切到**详细版**：逐条核验表、算据、来源都在那里；**原文**是同屏对照。

结论句里的数字由计数算出，不经模型之手 —— 说「1 处需要改」，往下翻就能找到那一处。

```
**大体可核，1 处需要改**；另有 1 处实算与原文声称不符；1 条查不到出处（是没核，不是没问题）。
```

简约版末尾固定写两句：这份报告由 AI 生成、**未经人工复核**；以及 —— 建议先自己读一遍原文，再对照这份核验。读解能省时间，不能替你判断。

## 能力边界（重要）

**它能做的**：抓正文（链接）、接受粘贴、转写上传的音视频（配 ASR 后从二手总结升为 L0 原声）、判体裁、核作者序与日期、逐条核说法、对可用算术验证的说法实算、生成带降级标注的报告。

**它做不到的**：

- 算不了需要**大矩阵、特征值、积分**的东西——白名单求值器只覆盖四则运算与初等函数。这类要上沙箱（见 `docs/ARCHITECTURE.md` §4）。
- 核不了**付费墙内**或需要登录的内容——请用粘贴入口。
- 保证不了**模型判「确证」就一定对**。所以报告里每一行都带依据，读者要自己看依据。

三条标签的含义，请务必分清：

| 标签 | 含义 |
|---|---|
| 已实算 | 数字由服务端求值器跑出来，可复算，且与原文声称值相差 ≤ 1% |
| 不符 | 算得出，但与原文声称值差超过 1% —— 这一档比「已实算」更有信息量 |
> 有**四道闸**是代码强制的，都在 `enforce_evidence()` 里：
> 1. **用正文证明正文** → 降「未核」
> 2. **依据援引的全是媒体/门户** → 降「半对」（判断依据是依据正文里出现的域名，不看模型自报的标签）
> 3. **依据援引了检索结果里没有的域名** → 降「半对」（读者点不开，等于无从核对，可能是模型自带的知识）
> 4. **来源全非一手** → 降「半对」
>
> 一手与否用**白名单制**判定，不用搜索接口的 authority 分 —— 那个分把「相关性」也算进去了，
> 实测三立新闻网、日经中文网、艾瑞咨询都能拿高分，但它们仍是转述。
> 名单外一律算「相关」，宁可保守；白名单覆盖不到的一手站点靠二次检索 `site:` 直检补进来。

| 待比对 | 算得出，但声称值是中文表述（如「每秒钟打5万次」）无法自动解析，两个数并排供人对照 |
| 仅供参考 | 算式无运算、全为常量，或原文根本没给声称值 |
| 未实算 | 表达式被安全规则拒绝，或算不出来——**按未验证对待** |
| 未核 | 拿不到原始来源，**不要当已确认** |

把「未算」说成「算过」，比不读解更坏：读者会拿一个没验证的数字去做判断。

## 支持哪些链接

| 来源 | 识别方式 | 能拿到什么 | 已知限制 |
|---|---|---|---|
| 微信公众号 `mp.weixin.qq.com/s/...` | 转义还原 + `js_content` 容器 | 标题、公众号名、发布时间、正文、公式（从 `data-formula` 还原） | 遇「环境异常」验证页抓不到；短链必须完整（少一个字符就报参数错误） |
| 微信视频号（元宝分享页 `yb.tencent.com/wx/...`） | 微信 UA 抓取 + 三层反转义取嵌入 JSON | 视频号主体、时长、视频文案、**元宝生成的总结** | 拿到的是**二手总结，不是原话**；无发布时间；见下节 |
| arXiv `arxiv.org/abs/...` | abs 页 + html 页 | 作者序（逐个取，可核「谁排第一」）、发布日期、摘要、全文 | 全文页会断流，失败自动退到摘要，并在报告里注明 |
| 普通网页 | 剥脚本样式，优先 `<article>` | 标题、正文 | 依赖**服务端直出 HTML**；见下方自测法 |
| PDF | 直接拒绝 | — | 提示改用「粘贴正文」 |
| 其他二进制 | 直接拒绝 | — | — |

**普通网页到底能不能抓，用三步自测**：

1. 浏览器里右键「查看网页源代码」，搜索正文里的一句话 —— **搜得到**，一般能抓。
2. 页面上内容要**等一会儿才出现**（滚动加载、单页应用）—— 抓不到，只拿到空壳，报告会提示「正文仅 N 字」。
3. 要登录、要付费、或弹出 Cloudflare 人机验证 —— 抓不到。

抓不到时的统一出路是**粘贴正文**入口。这不是妥协：粘进去的正文一样能定性、核验、实算，只是作者序与发布时间无从核对，报告会如实标「未核」。

**为什么不做浏览器渲染**：加无头浏览器会让部署体积和内存涨一个数量级，还要处理字体、沙箱、超时。判断是「粘贴一次」比「养一个 Chromium」便宜得多。

## 视频号：读的是「元宝的总结」，不是原话

视频号没有可抓的文本页面。可行路径是**让元宝先看一遍视频，再把元宝的分享链接交给本服务**：元宝会生成一段结构化总结，并把视频号主体、时长、视频文案一起带在页面里。

用微信 UA 请求那个分享页（`yb.tencent.com/wx/...`）能直接拿到这些内容——PC UA 只会返回「请在微信客户端打开」。

但这里有个必须讲清的层级差别：

| 层级 | 内容 | 是否可得 |
|---|---|---|
| L0 | 视频原声（口播原话） | 不可得 |
| L1 | 元宝对视频的总结 | 可得（约数百字） |
| L2 | 视频文案（发布者自述） | 可得 |
| L3 | 元数据：主体、时长、整理日期 | 可得（无发布时间、无播放量） |

因为缺 L0，**这份报告核的是总结，不是原话**。总结本身漏了什么、转述错了什么，本服务发现不了。所以视频模式下报告会强制多三样东西：

1. **来源层级声明**——报告头部与结尾都写明「L1 二手，非视频原话」。
2. **单列「需要回听的地方」**——视频特有的一类错：内容不错，是听写错了。这一节不再重复列错字，而是从校对结果里筛两批：改动涉及数字、专名或术语而依据不够硬的，以及模型提出疑问但没有动原声的。判由人来判。
3. **谁在说话**——账号是搬运方还是讲述者本人；文案里声明的头衔标「未核」，需查官方名录。

另外做一件纯算术的事：**用时长估口播字数，再看总结覆盖了多少**。示例那段视频时长 321 秒，按中文口播 4–5 字/秒估约 1284–1605 字，而元宝总结 302 字——**覆盖率约两成**。这个数字不进模型的手，由模板直接算出来写进报告。它回答的是「你看到的总结，可能漏了八成」。

### 接上 ASR：从「元宝总结」升到「原声」

先更正一个容易想当然的地方：**元宝的分享页里没有视频直链**，只有封面图（`coverUrl` 指向 `finder.video.qq.com`，但那是一张图）。所以原声只能由你提供——**在微信里「保存视频」，再上传到本服务**。

配好 ASR 后流程变成：

1. ffmpeg 抽音轨（16kHz 单声道 mp3，5 分钟约 2.4MB，直接绕开上传限制）；
2. 超过 20 分钟自动切片，转录后按片长偏移合并时间戳；
3. 来源层级从 L1 升为 **L0 原声转录**，报告新增一节「元宝总结 vs 原声」。

那一节才是这套东西真正有意思的地方：有了原话，才能判**元宝的总结有没有歪曲**。四类走形会被逐条挑出来——把条件句说成断言、把某人的观点说成经典原文、数字量级对不上、把否定说成肯定。

**首选 DeepSeek 的 ASR**（2026-11 开放的 `/v1/tools/asr`，国内直连、按音频时长计费）：

```bash
export LLM_API_KEY=sk-...          # 同一个 key 可直接用于 ASR
export ASR_BASE_URL=https://api.deepseek.com
export ASR_BACKEND=auto            # 地址含 deepseek.com 会自动选 deepseek 后端
```

它的约束必须知道，代码已按此适配：

| 约束 | 值 | 代码怎么处理 |
|---|---|---|
| 格式 | 只收 16-bit PCM WAV / Ogg Opus | 自动抽成 16kHz 单声道 WAV（mp3 会 400） |
| 时长 | 单文件 ≤ 120 秒 | 按 110 秒切片，留 10 秒余量 |
| 体积 | ≤ 8 MiB | 110 秒 16k 单声道 ≈ 3.5 MB，不会超 |
| 时间戳 | 不返回 | 报告只给全文，不做逐句定位 |
| 语种 | 自动检测，无 language 参数 | 中文无需配置 |

其他兼容端点（OpenAI、硅基流动、自建 faster-whisper 服务）把 `ASR_BACKEND` 设为 `openai` 即可；
不想用云端则 `pip install openai-whisper` 后设 `ASR_BACKEND=local`。

**DeepSeek 没有 prompt 参数，所以「给术语提示」这条路走不通** —— 官方文档明确只有 `file` 一个字段。想在中文口播上压错字率，改成转录之后修：

```bash
# 确定性替换，零成本
export ASR_FIX="几10万=几十万;及紫外=极紫外;拖住=托住"
# 让模型校对（一次额外调用，只修错字，不许改写）
export ASR_PROOFREAD=on
```

修正结果会在报告里单列一节「转录校对（已自动修正）」，逐条给出「原文 → 改为 → 依据 → 风险」。

**两节分工是 v2.3 改的**：以前「转录校对」列已修的、「疑似转述偏差」列存疑的，两节都在谈错字，后者经常空着。现在改成：

| 节 | 说什么 | 内容来源 |
| :-- | :-- | :-- |
| 转录校对 | **我改了什么**（全量清单） | 所有自动修正，带风险标记 |
| 需要回听的地方 | **你该亲自听哪几处** | 高风险改动 + 模型存疑未采纳的 |

风险分级看两件事：**改错的后果**（数字、专名改错会让后续核验建立在错前提上）与**改错的可能**（「规则替换」「上下文讲不通」这类依据硬，可直接采用；只说了「同音」而没给上下文证据的才建议回听）。两者都低的不进第二节，所以那一节经常不出现——**不出现就是没有高风险项，不是漏查**。

**没配 ASR 会怎样**：上传后明确报「无法转写：未配置」，不会假装做过转录。

**隐私提醒**：音频会上传到你所选的服务商。涉及未公开内容时，用本地 `whisper`。

## 语音画像：这段录音是什么话、谁在说

DeepSeek ASR 的接口不返回语种，也不返回置信度（官方文档明说「语言从音频自动检测」，
但响应里只有 `text` 与 `duration_ms`）。所以「这是普通话还是方言、是真人还是 TTS」
只能自己算，`server/voice.py` 用两条独立证据：

| 证据 | 怎么来 | 能回答什么 |
|---|---|---|
| 声学 | 读 WAV 波形：语速、音量起伏、基频波动、停顿长短的离散度 | 念稿/合成音 vs 真人即兴 |
| 文本 | 读转录：字符集、口语填充词、方言标志词、自我修正 | 语种、方言倾向 |

**为什么值得做**：需要回听的那一节经常是空的。以前只能猜「模型偷懒了」，现在能看出来
——如果是 TTS 或专业配音，发音标准、断句规整，ASR 本来就几乎不出错，空是**正确结果**；
如果是带方言的即兴讲述却一条都没列，那才需要怀疑。

报告里这一节严格分成「实测」与「推断」两栏，推断一律写「更像」「疑似」：

```
| 语种 | 中文 |
| 方言 | 未检出方言用词（倾向普通话） |
| 说话方式 | 真人自然讲述 |

实测：汉字 1745 个、语速 4.8 字/秒、有声占比 87%、音量起伏 0.48、
      基频波动 0.41、停顿 12 段平均 0.64 秒（离散度 0.41）、口语填充词 6 处
推断：音量起伏大、有填充词、停顿不规律 —— 更像即兴讲述
影响：即兴讲述断句粘连、吞字最多，ASR 错字率通常高于念稿
```

判定用的是**停顿长短的离散度**而不是停顿次数 —— TTS 的句间停顿一样多，
区别在于它每次都精确 0.3 秒，而真人从 0.1 到 1 秒乱来。

音频拿不到时（比如只贴了文章链接）这一节自动跳过，只给文本侧的语种判断，不影响主流程。

## 抓取也可以交给 DeepSeek Fetch

`POST /v1/tools/fetch` 把网页取成 Markdown，专门对付本地正则搞不定的页面（公众号反爬、需要渲染的站）。

默认 `FETCH_BACKEND=auto`：**先本地解析，失败才回退 Fetch**。这样作者序、发布时间这些本地才解析得出来的字段不会丢——只有抓不到正文时才交给它兜底，并在报告里注明「作者、发布时间未解析，相关核对标未核」。

想反过来（Fetch 优先，强反爬场景更省事）：

```bash
export FETCH_BACKEND=deepseek
export DFS_API_KEY=sk-...      # 留空则复用 LLM_API_KEY
```

## 未核项自动溯源

报告里最常出现的一列是「未核」——不是判断失败，是**没有出处就不许下结论**。Search 接口接上之后，这一步可以自动补：

```
核验 → 只挑「未核」的条目 → 每条检索一次 → 结果回灌 → 重新判定
```

三条自我约束写死在代码里：

1. **只查「未核」的**，已能判定的不重复花钱（`SEARCH_MAX_ITEMS` 默认 3 项，控制成本）；
2. **低质量结果不能单独支撑「确证」**——要求 `authority ≥ 3` 或 `rerank_score ≥ 1.5`，
   只拿到转载博客的一律保持「未核」；
3. **检索失败不影响主流程**，报告里如实写「未溯源」。

判定被更新时，核验表会多出「出处」列：

| # | 判定 | 依据 | 出处 | 应改为 |
|---|---|---|---|---|
| 2 | 确证 | 据 ASML EUV 说明 | asml.com | 无需修改 |
| 3 | 未核 | 检索只得到低质量转载，不足以定论 | — | 查 Gartner 份额报告 |

配置（与 ASR 共用 DeepSeek 的 key）：

```bash
export LLM_API_KEY=sk-...
export SEARCH_ENABLED=auto   # auto 表示有 key 就启用；off 可关掉
```

## 界面

- **报告三档**：「简约」一句话结论 + 站得住的部分 + 需要改的；「详细」逐条核验表与算据；「原文」Markdown 源码。默认打开简约 —— 一次全给等于把判断和依据堆在同一屏，读者多半只看前者。
- **七个阶段实时显示**：抓取 / 转写 / 定性 / 核验 / 溯源 / 实算 / 成稿，点「慧惠读解」后才出现。灰 = 没跑到、绿 = 完成、橙 = 跑完但有话说（如「无可算项」）、红 = 断了；进行中有呼吸动效。详见 [`docs/RUN_STATES.md`](docs/RUN_STATES.md)。
- **数据去向写在首页**：「你的数据你做主，查看隐私条约」折叠卡列出三条承诺，并带「立即删除我上传的文件」按钮（接 `POST /api/upload/drop`）。
- **窄屏（≤640px）表格自动变卡片**：一行一张卡，字段名做前缀，不用左右拖着读长句。
- 可下载 `.md` 存档（iOS Safari 会存进「文件」App）。
- 一次读解约 1–2 分钟，不会白屏干等。

## 部署

生产环境建议套一层反向代理（SSE 必须关缓冲）：

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_buffering off;          # 关键：否则流式事件会被攒着一次性吐出
    proxy_read_timeout 300s;
}
```

Docker：

```bash
docker build -t deep-read .
docker run -p 8000:8000 -e LLM_API_KEY=sk-... deep-read
```

环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM_API_KEY` | 空 | 未设置时服务可启动，但读解会明确报错（不降级为假报告） |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | 任何 OpenAI 兼容端点 |
| `LLM_MODEL` | `deepseek-chat` | 模型名 |
| `PORT` / `HOST` | `8000` / `0.0.0.0` | 监听；**命令行 `-p` / `--host` 优先于这两个变量** |
| `RATE_LIMIT_PER_HOUR` | `10` | 每 IP 每小时次数 |
| `REDIS_URL` | 空 | 限流后端。空 = 进程内存（单机）；填地址 = Redis（多副本）。**填了但连不上 → 503，不回退内存** |
| `RL_SALT` | `deepread-v1` | 限流键的盐：Redis 里存 `sha256(盐+IP)` 前 32 位，不留明文 IP。换盐 = 旧键作废，等同全员额度重置 |
| `TRUSTED_PROXIES` | 空 | 反代后取真实 IP 的可信代理名单（IP 或网段）。**空 = 不信任任何代理头**，多副本部署必须填 |
| `MAX_CONCURRENT` | `8` | 同时进行的任务上限；满了回 503，不排队 |
| `SLOT_WAIT_SEC` | `20` | 等额度的秒数，等不到即 503 |
| `MAX_UPLOAD_MB` | `300` | 单个上传音视频上限 |
| `UPLOAD_TTL_HOURS` | `24` | 上传件兜底保留期：分析结束会立刻删，没分析的到点删 |
| `CA_BUNDLE` | 空 | 指定根证书（公司/代理场景），也可用系统标准的 `SSL_CERT_FILE` |
| `INSECURE_TLS` | 空 | 设为 `1` 关闭证书校验，**仅供本机调试** |
| `ASR_BACKEND` | `auto` | `auto` / `openai` / `local` |
| `ASR_BASE_URL` | `https://api.deepseek.com` | 转录端点。`ASR_BACKEND=auto` 时地址含 `deepseek.com` 就走 DeepSeek `/tools/asr`，否则走 OpenAI 兼容端点 |
| `ASR_API_KEY` | 空 | 不设则无法转写（保持 L1 元宝总结） |
| `ASR_MODEL` | `whisper-1` | 或本地 whisper 的 `base`/`small`/`medium` |
| `ASR_LANGUAGE` | `zh` | 识别语种 |
| `ASR_PROMPT` | 空 | 术语提示，压低专名错字率 |
| `ASR_FIX` | 空 | 确定性替换，格式 `错=对;错=对`，零成本 |
| `ASR_PROOFREAD` | `off` | `on` 则让模型校对同音字/数字误识，一次额外调用 |
| `SEARCH_ENABLED` | `auto` | 未核项自动溯源；`auto` 表示有 key 就启用，`off` 关掉 |
| `SEARCH_COUNT` | `6` | 每次检索取几条（1–50） |
| `SEARCH_MAX_ITEMS` | `3` | 最多溯源几项，控制成本 |
| `FETCH_BACKEND` | `auto` | 抓取后端：`auto`（本地优先、失败回退）/ `deepseek` / `local` |
| `DFS_API_KEY` | 空 | DeepSeek Fetch 的 key，不设则复用 `LLM_API_KEY` |
| `DFS_BASE_URL` | `https://api.deepseek.com` | DeepSeek Fetch 端点 |

## 报错 SSLError？先跑体检

Windows 上最容易撞见这一类失败：

```
SSLError(SSLCertVerificationError(1, '[SSL: CERTIFICATE_VERIFY_FAILED]
certificate verify failed: unable to get local issuer certificate'))
```

**这不是网络不通，也不是 key 错了，是证书链找不到。** 先跑：

```powershell
python3 server/doctor.py
```

它会打印：Python 版本、certifi 路径与证书数、所有相关环境变量（代理里的账号密码会自动遮蔽）、
对 `api.deepseek.com` 的实际 TLS 握手结果（含颁发者与有效期），最后给出对应出路。

三条常用修法：

```powershell
# 1) 升级根证书（最常见）
python3 -m pip install --upgrade certifi
python3 -m pip install python-certifi-win32   # Windows 上让 certifi 用系统证书存储

# 2) 公司/代理的根证书
$env:CA_BUNDLE="D:\path\to\company-ca.pem"

# 3) 本机调试、明确知情时的最后手段（会关闭全部校验，别在真实环境用）
$env:INSECURE_TLS="1"
```

程序默认**不关闭校验**：那只会把问题从「跑不起来」变成「跑起来但不知道在跟谁说话」。
所有出站请求都走 `server/net.py` 这一个出口，统一 CA、超时、两次重试，并把底层异常翻成可操作的提示。

## 安全

- **服务端不执行模型生成的任意代码**。所有表达式经白名单 AST 求值：只允许算术与少数初等函数，拒绝属性访问、下标、推导式、lambda、导入，幂指数有上限，结果须为有限实数。攻击用例见 `server/test_safe_eval.py`。
- **API key 只在服务端**。前端永不接触；`/api/health` 只返回「是否已配置」。
- **限流默认在进程内存**（`REDIS_URL` 为空时，单机够用）；多副本必须配 Redis。Redis 模式是滑动窗口（ZSET + Lua 原子判定），429 带 `Retry-After`，额度可用 `dr:cfg:limit` 热调，细节见 [`docs/RATE_LIMITING.md`](./docs/RATE_LIMITING.md)。限流只按 IP，换 IP 仍可绕过，公开部署还需要叠加其他维度。
- 未经授权大量抓取第三方站点可能违反其条款，请自行评估。

## 数据与隐私

- **不记录读解内容**：没有业务日志；报告不落盘，只存在于当次响应流里。
- **上传的音视频**：分析结束即删；上传后没点「慧惠读解」的，按 `UPLOAD_TTL_HOURS`（默认 24 小时）自动清掉。也可以主动删：`POST /api/upload/drop {"id": "..."}`。
- **限流只存哈希后的 IP**（`sha256(盐+IP)` 前 32 位），随 1 小时滑动窗口过期，Redis 里没有明文地址。
- **没有账号体系**：不采集浏览、设备、位置信息。
- 抓取来的正文只在本次读解使用，不写库。
