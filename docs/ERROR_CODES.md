# 错误码表（ERROR_CODES）

`server/codes.py` 的人读版。**码稳定，文案可变**：码一旦发布不改含义，`error` / `hint` 的措辞随时可调。测试断言码，不断言文案。

三条规矩（与设计文档第十一节一致）：

1. **按码列行，不按 condition 合并。** DR-1001 与 DR-2001 共用 `incompleteRequest`，但一个发生在读解、一个发生在上传，用户动作完全不同，各占一段。condition 是内部统计口径，不是分节依据。
2. **「排障」行必须回答「要不要看日志」。** 码表 `log` 为「否」的写「不需要看日志」并给替代检查点；为「是」的写清看哪几个字段。
3. **段落标题固定为 `### DR-xxxx · 中文短名`。**

本文件与 `server/codes.py` 的码集合必须双向一致，由 `server/test_guards.py` 的守门一校验——删了码没删段、或加了段没加码，都会红。

线上响应体（十二字段）：

```json
{"ok": false, "code": "DR-1005", "condition": "textTooShort",
 "error": "正文太短（不足 200 字）", "hint": "粘贴完整内容，或改用链接 / 上传音视频",
 "retryable": false, "retry_in_seconds": null, "request_id": "8f3ac21b",
 "responsibility": "user", "level": "fail", "show_code": false, "show_diag": false}
```

`level` / `show_code` / `show_diag` 由 `codes.present()` 算，前端照此绘制，不自己判断。

## 1xxx · 输入

### DR-1001 · 请求内容为空

- 用户看到：请求内容为空 · 重新提交
- 触发：`POST /api/analyze` 或 `POST /api/upload/drop`，`Content-Length` 缺失或 ≤ 0
- 何时加：任何新加的 POST 路由若收 JSON，都要自带这条校验，别等 JSON 解析报错
- 排障：不需要看日志。常见成因是客户端空提交（表单没填、fetch 漏 body）

### DR-1002 · 内容太大

- 用户看到：内容太大（上限 {limit}）· {advice}
- 触发：`/api/analyze` 请求体 > 260 KB（中文约 8.6 万字）；`/api/upload/drop` 请求体 > 4 KB
- 何时加：调 `BODY_LIMIT` 时同步改本行的说法；`{limit}` 与 `{advice}` 由调用点传入，不在码表写死数字
- 排障：不需要看日志。先看客户端是否把整篇长文一次贴上；确属长文就引导分段

### DR-1003 · 请求格式有误

- 用户看到：请求格式有误 · 刷新页面后重试
- 触发：POST 的 body 不是合法 JSON（`/api/analyze` 与 `/api/upload/drop` 两处）
- 何时加：与【DR-1001】同为请求体校验的前两道闸，新增路由时一起带
- 排障：不需要看日志。多半是前端拼 body 时漏了 `JSON.stringify`，或反代改写了 body

### DR-1004 · 没有可读解的内容

- 用户看到：没有可读解的内容 · 提供链接、粘贴正文，或上传音视频
- 触发：`/api/analyze` 的链接、正文、`upload_id` 三者皆空；pipeline 的 extract 阶段走到「无可用输入」分支（同一码两态都用）
- 何时加：与 pipeline 的输入判定保持一致；改「什么算有输入」要两处同改
- 排障：不需要看日志。看前端是否把空白字符串当成有输入提交了

### DR-1005 · 正文太短

- 用户看到：正文太短（不足 200 字）· 粘贴完整内容，或改用链接 / 上传音视频
- 触发：`POST /api/analyze`，正文非空、无链接、无上传件，且字数 < 200
- 何时加：与 pipeline「≥200 字走正文」的判定保持一致。这两个阈值是一件事，改一处必改两处
- 排障：不需要看日志。先确认调用方是否截断了正文（比如前端预览截断后又提交）

### DR-1006 · 正文过长

- 用户看到：正文过长（上限 20 万字符）· 分两段读解
- 触发：正文长度 > 200000 字符（字节闸 `BODY_LIMIT` 先拦，这条是字符闸）
- 何时加：两道上限（字节 / 字符）要一起改，否则会出现「字节过了字符不过」或反之
- 排障：不需要看日志。200000 字中文约 600 KB，实际会先被【DR-1002】拦住——这条主要兜住 ASCII 长文

### DR-1007 · 接口不存在

- 用户看到：接口不存在 · 检查地址或刷新页面
- 触发：GET 到未知路径；POST 到除 `/api/analyze`、`/api/upload`、`/api/upload/drop` 之外的路径；`/og.jpg` 读取失败也复用此码
- 何时加：新增路由要在这里与「路由表」两处同步，否则新路由的 404 会落到默认分支
- 排障：不需要看日志。看请求路径是否被反代改写、或前端调了旧版本接口

## 2xxx · 上传

### DR-2001 · 上传中断

- 用户看到：上传中断 · 重新上传
- 触发：`POST /api/upload`，`Content-Length` 缺失或 ≤ 0
- 何时加：与【DR-1001】同为「请求体为空」，但这里发生在上传路径，用户动作是重传而不是重填
- 排障：不需要看日志。看客户端是否在 `send()` 前就断开了

### DR-2002 · 文件超过上限

- 用户看到：文件超过上限 300 MB · 换成更小的文件，或先压缩
- 触发：`POST /api/upload` 的 `Content-Length` > `MAX_UPLOAD`（默认 300 MB，可由 `MAX_UPLOAD_MB` 调）
- 何时加：改 `MAX_UPLOAD_MB` 时同步改文案里的数字（`{limit}` 由调用点传入，取自同一常量）
- 排障：不需要看日志。超限时服务端不读 body 直接回，先确认不是客户端重试导致的重复上传

### DR-2003 · 不支持的文件类型

- 用户看到：不支持的文件类型 · 支持这些格式：{options}
- 触发：上传文件扩展名不在 `ALLOWED_EXT`（mp4 / mov / m4a / mp3 / wav / aac / flac / webm / mkv / ogg / amr / opus / silk）
- 何时加：给 `ALLOWED_EXT` 加格式时，`{options}` 会自动跟着变——它由集合生成，不要手写
- 排障：不需要看日志。看 `ext` 是否为空（无扩展名）或大小写（已统一小写比较）

### DR-2004 · 上传标识无效

- 用户看到：上传标识无效 · 重新上传
- 触发：`/api/analyze` 的 `upload_id` 含非字母数字字符；`/api/upload/drop` 的 `id` 不是 16 位字母数字
- 何时加：`upload_id` 的生成规则（`uuid4().hex[:16]`）若改长度，两处校验要同改
- 排障：不需要看日志。看前端是否把 id 截断或加了引号

### DR-2005 · 文件已过期

- 用户看到：文件已过期（上传超 24 小时）· 重新上传
- 触发：`upload_id` 合法但 `UPLOAD_DIR` 里找不到对应文件（`UPLOAD_TTL` 默认 24 小时，惰性清扫）
- 何时加：调 `UPLOAD_TTL` 时同步改文案里的时长
- 排障：不需要看日志。先确认是不是同一台机器（多副本部署时文件不在同机，会被误判为过期）

### DR-2006 · 上传不完整

- 用户看到：上传不完整 · 重新上传
- 触发：读到的字节数 != 声明的 `Content-Length`（连接中断、客户端提前关闭）
- 何时加：与【DR-2001】的区别是「声明了长度但没传够」，两者用户动作相同、诊断含义不同
- 排障：不需要看日志。看服务端磁盘是否写满、或客户端超时设置是否过短

## 3xxx · 额度与并发

### DR-3001 · 本小时额度已用完

- 用户看到：本小时额度已用完（每小时 {limit} 次）· 约 {minutes} 分钟后恢复
- 触发：`/api/analyze` 或 `/api/upload` 触发限流（默认每小时 20 次，`RATE_LIMIT_PER_HOUR`）
- 何时加：`{limit}` 取自 `LIMITER.current_limit()`，`{minutes}` 与 `retry_in_seconds` 必须同由一个秒数派生，不许各算一套
- 排障：不需要看日志。响应头 `Retry-After` 与 body 的 `retry_in_seconds` 一定同值；不同值说明有人绕过 `_exceeded` 自己拼了响应

### DR-3002 · 同时读解的人较多

- 用户看到：同时读解的人较多 · 等一两分钟再试
- 触发：并发槽占满（`MAX_CONCURRENT` 默认 8），等 `SLOT_WAIT` 仍拿不到槽
- 何时加：调 `MAX_CONCURRENT` 或 `SLOT_WAIT` 时来改这句
- 排障：不需要看日志。服务端会主动断开连接（不让线程卡在信号量上），客户端会看到连接关闭而非 5xx

### DR-3003 · 服务暂时繁忙

- 用户看到：服务暂时繁忙 · 等一两分钟再试
- 触发：限流后端（Redis）连接失败、超时或熔断中，按 fail closed 处理为禁止
- 何时加：3xxx 里唯一记日志的码——它意味着「基础设施出问题了」，别的 3xxx 是正常业务兜底
- 排障：要看日志。看 `code=DR-3003` 的连续出现；同时查 Redis 是否可达、`rate_limit_backend` 是否被降级成内存实现

## 4xxx · 外部依赖

### DR-4001 · 服务端尚未配置模型

- 用户看到：服务端尚未配置模型 · 把这个诊断信息发给我们
- 触发：pipeline 的 extract 阶段发现 `llm.is_configured()` 为假（缺 `LLM_API_KEY`）
- 何时加：部署漏配 key 才会触发；不降级出假报告，这属于设计选择而非缺陷
- 排障：要看日志。但更快的路径是打开 `/api/health` 看 `llm` 字段是否为 false

### DR-4002 · 模型调用失败

- 用户看到：模型调用失败 · 稍后重试（已自动重试 2 次）
- 触发：triage 阶段 `llm.LLMError`（上游超时、限流、返回不可解析）
- 何时加：重试次数若调整，这句话要跟着改
- 排障：要看日志。看 `exc` 字段的异常摘要；连续出现说明上游服务出问题，不是用户的问题

### DR-4003 · 这个链接抓不到内容

- 用户看到：这个链接抓不到内容 · 改用「粘贴正文」，或上传音视频
- 触发：extract 阶段 `FetchError`，且**没有**备选的上传件；有上传件时降级继续、不报此码
- 何时加：新增加密订阅源、登录墙站点时先看这里，别急着报错——可以考虑加降级
- 排障：要看日志。看 `exc` 是 DNS、TLS 还是 4xx/5xx；403 多为反爬，教用户改用粘贴正文

### DR-4004 · 音视频转写失败

- 用户看到：音视频转写失败 · 换一个文件，或粘贴正文
- 触发：transcribe 阶段 `asr.ASRError`（上游 413 / 429 / 5xx、返回空转录）
- 何时加：与【DR-4005】的分界是「模型失败」还是「文件读不出」，不要把两条合成一条
- 排障：要看日志。看 `exc` 里的上游状态码；429 是限流，5xx 是上游故障

### DR-4005 · 这个文件读不出来

- 用户看到：这个文件读不出来 · 换格式重传
- 触发：transcribe 阶段 `media.MediaError`（容器损坏、缺 ffmpeg、解不出音轨）
- 何时加：v2.31 之前这条被并进【DR-4004】，成了永远走不到的码；拆开后语义才与用户动作对齐
- 排障：要看日志。看 `ffmpeg` 字段（`/api/health`）是否为 false；缺 ffmpeg 时所有音视频都会走到这里

### DR-4006 · 服务端尚未配置转写

- 用户看到：服务端尚未配置转写 · 把这个诊断信息发给我们
- 触发：有上传件但 `asr.is_configured()` 为假（缺 `ASR_BACKEND` / key）
- 何时加：与【DR-4001】对称：一个缺模型、一个缺转写，部署自检时一起看
- 排障：要看日志。但 `/api/health` 的 `asr` 与 `asr_backend` 字段更直接

## 5xxx · 服务端自身

### DR-5001 · 页面文件缺失

- 用户看到：页面文件缺失 · 把这个诊断信息发给我们
- 触发：`GET /` 或 `/index.html` 时 `web/index.html` 读取失败（镜像里没带上、路径不对）
- 何时加：几乎只会在部署出错时出现；出现即说明镜像构建有问题
- 排障：要看日志。查容器内 `web/` 是否为空；`/api/health` 仍可用说明只是静态文件缺失

### DR-5002 · 服务器存储异常

- 用户看到：服务器存储异常 · 稍后重试；持续失败请发诊断信息
- 触发：上传写盘 `OSError`（磁盘满、权限不足、临时目录不可写）
- 何时加：与【DR-2006】的区别是「写不进去」还是「没传够」，前者是服务端问题
- 排障：要看日志。`exc` 里通常是 `OSError: [Errno 28] No space left on device`；顺手清 `$TMPDIR/deepread_uploads`

### DR-5003 · 服务异常

- 用户看到：服务异常 · 把这个诊断信息发给我们
- 触发：所有没被前面码接住的异常（app 层兜底帧、pipeline 的 triage 兜底帧）
- 何时加：**这是兜底码，不主动加。** 同一形状的错误出现三次以上，就该为它造一个专用的码
- 排障：要看日志。`exc` 里有异常类型与消息，页面只显示「服务异常」与追踪号——用户报障时把 `rid` 对上日志即可
