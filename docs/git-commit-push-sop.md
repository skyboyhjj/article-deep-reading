# Git 提交与推送 SOP（两阶段制）

> 版本 v1.1 ｜ 更新 2026-11-22 ｜ 适用范围：全局（所有项目通用）
> 依据：`ecad0f1` 实操复盘，以及一次「把『执行吧』误读为推送授权」的越权事故。

---

## 0. 目的

把「改代码」到「上远程」拆成两个**互不越界**的阶段，确保内容进入远程之前，用户拥有完整的复核窗口。

核心不变式：**本地可逆，远程不可逆。**

---

## 1. 指令语义

| 指令 | 授权范围 | 禁止 |
|---|---|---|
| **执行** / **提交** | 完成工作 + 提交到**本地** git 库 | 严禁 push |
| **提交到GitHub** / **推送** / **推到远程** | 明确授权 push | —— |
| **执行并推送** | 明确同时授权两阶段 | 仍须分阶段报告 |

单句「执行吧」若上文不足以唯一确定阶段，**先问，不得推断**。

---

## 2. 状态机

```
工作区变更 ──[阶段 A: commit]──> 已提交·未推送 ──[阶段 B: push]──> 已推送
                                      ↑
                              用户复核窗口，不得跳过
```

---

## 3. 阶段 A · commit

| 项 | 规范 |
|---|---|
| 触发 | `执行`、`提交`（未提 GitHub） |
| 前置 | 报告拟提交文件清单 + 提交信息草案 + 是否拆分逻辑单元 |
| 预检三查 | `git status --short`（范围）、`git diff -- <file>`（内容）、`git status -sb`（ahead） |
| 动作 | 只 `git add` 清单内文件（**禁用 `git add -A`**）→ `git commit` |
| 出口 | 报 commit hash + 文件清单 + 显式「**未推送**」+ ahead N，止步 |
| 可逆 | 未推送前可 `git reset --soft HEAD~1` / `git commit --amend` |

---

## 4. 阶段 B · push

| 项 | 规范 |
|---|---|
| 触发 | `提交到GitHub`、`推送`、`推到远程` |
| 前置 | 报待推区间 `base..tip` + 是否连带未确认祖先 + 目标远程/分支 |
| 动作 | 获确认后 `git push origin <branch>` |
| 出口 | 核 `git status -sb` 为 **ahead 0**；不以 push 输出作为成功判据 |
| 门禁 | 禁止 force-push main；禁止改写已推送历史 |

**推送前清单模板**

```
待推区间：<base>..<tip>
提交清单：
  1. <hash> <标题>
  2. <hash> <标题>
连带祖先：无 / 有（<hash>，未获确认）
目标：origin/<branch>
```

---

## 5. 阶段门禁（不变式）

1. 两阶段严格分离；未获同时授权时，不得在一条指令内既 commit 又 push。
2. 「已提交·未推送」是用户的复核窗口，不得自行跳过。
3. 推送必报清单，**包括被动带上的祖先提交**。
4. 禁 force-push main，禁改写已推送历史。

---

## 6. 边界条件（复盘固化为规范）

| # | 边界 | 规范 |
|---|---|---|
| B1 | 授权合并 ≠ 过程合并 | 即使收到「执行并推送」，报告仍分 A/B 两阶段呈现 |
| B2 | 推送授权可中断的唯一例外 | 待推区间含**未确认的祖先提交** → 停下确认再推 |
| B3 | 仅收到【执行】 | 必须止步阶段 A，显式写「未推送」 |
| B4 | 模糊指令 | 「执行吧」无法唯一确定阶段 → 先问 |
| B5 | 成功判据 | push 后必须核 ahead 0 |
| B6 | 忽略规则 | 用 `git check-ignore -v <path>` 验证命中，不靠肉眼 |
| B7 | 已推送内容需移除 | 不改写历史：revert + 本地保留 + `.gitignore` |
| B8 | 操作范围 | 不得超出已确认清单（文件、提交、分支） |

---

## 7. 异常与回退矩阵

| 状态 | 期望 | 做法 |
|---|---|---|
| 已提交、未推送 | 改内容 / 改信息 | `git reset --soft HEAD~1` 重组；或 `--amend` |
| 已提交、未推送 | 拆分成多个提交 | `reset --soft` 后分批 add + commit |
| 已推送 | 内容有误 | `git revert <hash>` 追加反向提交 |
| 已推送 | 需本地保留文件 | revert + 本地恢复 + `.gitignore` |
| 已推送 | 提交信息有误 | 不 amend；接受或 revert 后重提 |
| 推送被拒（非快进） | 远程有新提交 | `git fetch` 后 rebase/merge，**不 force** |

---

## 8. 执行清单

**阶段 A**

- [ ] 三查已完成（范围 / 内容 / ahead）
- [ ] 文件清单与提交信息已报告
- [ ] 只 add 列明文件
- [ ] 提交后报 hash + 「未推送」+ ahead N

**阶段 B**

- [ ] 已收到明确推送指令
- [ ] 待推区间与提交清单已报告
- [ ] 无未确认的连带祖先
- [ ] push 后 ahead 0 已验证

---

## 9. 案例对照

| 维度 | 事故（越权） | 规范执行（`ecad0f1`） |
|---|---|---|
| 指令解读 | 「执行吧」推断为推送 | 「执行并推送吧」明确授权 |
| 提交范围 | 未列清单即提交 | 三查 + 单文件 |
| 推送告知 | 事后解释连带 2 个提交 | 事前报区间，仅 1 个 |
| 结束状态 | 远程含不愿推送内容 | ahead 0 且内容符合预期 |
