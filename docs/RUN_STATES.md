# 运行状态与配色

对象：`web/index.html` 里的七个阶段标签（抓取 / 转写 / 定性 / 核验 / 溯源 / 实算 / 成稿）
守门：`server/test_ui_contract.py` 的 `TestHomeTheme`

## 一、五个状态

| 状态 | 边框 | 文字 | 底色 | 什么时候出现 | 字/底对比度 |
| :-- | :-- | :-- | :-- | :-- | --: |
| 未跑 | `#d4c9a8` 沙 | `#6f6f6f` | `#fffef5` | 页面初始，或本次没触发 | 4.96 |
| 进行中 | `#b9c9c0` | `#2e5f5f` 墨青 | `#eef4f0` 浅青 | 收到 `status: run` | 6.45 |
| 完成 | `#b7d3c4` | `#2f7d5d` 草绿 | `#eef7f2` 浅绿 | `status: ok` | 4.56 |
| 有保留 | `#e2cfa6` | `#94600f` 橙 | `#fdf6e9` 浅黄 | `status: warn`（目前只有实算会用） | 4.96 |
| 失败 | `#e0b6b6` | `#b23b3b` 红 | `#fbeeee` 浅粉 | `status: fail` | 5.18 |

**颜色只表达四件事**：灰 = 没跑到，绿 = 正常完成，橙 = 跑完但有话说，红 = 断了。进行中属于绿系偏青。

一次纯文本读解跑到实算时的典型样子：抓取 / 定性 / 核验 / 溯源 / 成稿是绿的，**转写是灰的**（没有音视频，这一步没触发，不是失败），**实算是橙的**（跑过了，但这次「无可算项」）。

## 二、状态由什么驱动

```
服务端 SSE 事件 {stage, status}
   ↓
handleEvent() 判断 status
   ├ run      → setStage(stage, "run")    变青 + 文字后加「…」
   ├ ok/warn  → setStage(stage, 同名类)
   ├ fail     → setStage(stage, "fail")
   └ info     → 不改标签（如「2 项确证被降级」这类补充说明）
   ↓
done 时兜底：服务端若漏发 render ok，前端补一次 setStage("render","ok")
```

三条容易踩的规则：

1. **`info` 不染色。** 核验后的降级提示是 `info`，只进下方日志行。若给它着色，读者会以为那一步失败了。
2. **每次开始全部回灰。** `resetStages()` 先把七个标签清回默认，所以第二次读解能看到「一片灰 → 逐个变绿」，不残留上一轮的颜色。
3. **`done` 有兜底。** v2.12 实测过「成稿」永远转圈：服务端只发了 `render` 的 `run`，随后直接 `done`。前端因此补了一次 `ok`。

另：v2.22 起整条标签**初始隐藏**（`display:none`），点「帮我读解」时才显示，与第一个 `run` 事件几乎同时。

## 三、为什么是这几个颜色

### 3.1 对比度都过 WCAG AA

小号文字（12.5px）要求 ≥ 4.5:1。初版有两处不达标，已修：

| 状态 | 初版 | 现在 |
| :-- | --: | --: |
| 未跑（`#888` → `#6f6f6f`） | 3.50 | **4.96** |
| 有保留（`#a86a12` → `#94600f`） | 4.13 | **4.96** |

「有保留」恰恰是最该被看清的一档，初版反而最淡。

### 3.2 进行中靠动效，不靠颜色

| 对比项 | 数值 |
| :-- | :-- |
| 进行中与完成的底色 RGB 距离 | **3.6**（几乎同色） |
| 边框 | `#b9c9c0` vs `#b7d3c4`，肉眼难分 |

两者色域已经贴在一起，继续调色只会是同族。所以改用呼吸动效：

```css
.st.run{animation:stpulse 1.2s ease-in-out infinite}
@keyframes stpulse{0%,100%{opacity:1}50%{opacity:.62}}
@media (prefers-reduced-motion: reduce){ .st.run{animation:none} }
```

一呼一吸比任何颜色都好认，也不破坏「绿 = 正常」的语义。最后一行是必须的：开了「减少动态效果」的系统会自动静默。

## 四、改色时的四条硬规矩

1. **对比度必须 ≥ 4.5**（小号文字）。`TestHomeTheme.test_stage_colors_meet_wcag` 会解析 CSS 并逐态计算，掉下去就红。
2. **语义不许混用**：灰只能表示「没跑」，不能拿来表示「跳过」或「不重要」—— 那会让读者误判这次读解做过什么。
3. **动效必须有降级**：`prefers-reduced-motion` 缺了会红（`test_stage_run_distinguished_by_motion`）。
4. **新增状态要先有语义**：现在只有 ok / warn / fail 三种结束态，都能在 `pipeline.py` 里指到具体分支（例如 `compute` 的 `ok if (real or bad) else warn`）。加第四种之前，先想清楚它在报告中意味着什么。
